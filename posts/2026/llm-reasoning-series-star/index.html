Generating an explicit step-by-step rationale before a final answer improves language-model accuracy on arithmetic, commonsense, and mathematical reasoning. The difficulty is in inducing the behavior. Two methods were available before this work, and each has a cost (Zelikman et al. 2022). The first is to fine-tune on a dataset of rationales, written either by human annotators or by hand-crafted templates; manual annotation is expensive and must be redone for each new task, and templates only work where a general solution is already known. The second is few-shot prompting with a handful of rationale examples in the context, which requires no new data but underperforms a model fine-tuned on a large dataset to predict answers directly.

STaR — the Self-Taught Reasoner — avoids both costs by using the model’s own rationales as training data (Zelikman et al. 2022). The model is few-shot prompted to produce a rationale and an answer for each problem in a large answer-labeled dataset. Rationales whose final answer matches the ground-truth label are kept; the rest are discarded. The model is fine-tuned on the kept rationales, and the improved model generates the next round of data. The loop repeats until performance plateaus. A second mechanism, rationalization, supplies the correct answer as a hint so the model can produce a usable rationale for problems it could not solve on its own, extending the training signal to the difficult tail of the dataset.

1 The Bootstrapping Loop

The setup is a pre-trained model M, a dataset \mathcal{D} = \{(x_i, y_i)\}_{i=1}^{D} of problems with answers but no rationales, and a small prompt set \mathcal{P} = \{(x^p_i, r^p_i, y^p_i)\}_{i=1}^{P} of examples that do include intermediate rationales, with P \ll D (the paper uses P = 10). Each example to be solved is prefixed with the full prompt set, x_i = (x^p_1, r^p_1, y^p_1, \dots, x^p_P, r^p_P, y^p_P, x_i), so the model continues the pattern: it emits a rationale \hat{r}_i followed by an answer \hat{y}_i.

The filtering rule rests on a single assumption: a rationale that leads to the correct answer is, on average, of higher quality than one that leads to a wrong answer. The answer label is therefore used as an automatic, if noisy, quality filter — only rationales with \hat{y}_i = y_i are retained. No model of rationale correctness is trained, and no human inspects the kept rationales. This is what makes the loop scalable: the only supervision required is the answer that the dataset already provides.

Fine-tuning on the filtered set produces a stronger model, which generates a larger and higher-quality set on the next pass, which in turn supports further fine-tuning. Improvements in rationale generation improve the training data, and improvements in the training data improve rationale generation.

2 Why Fine-Tune From the Original Model Each Iteration

At each iteration the paper fine-tunes the original pre-trained M on the newly collected dataset, rather than continuing to train the model from the previous iteration. Continuing to train the same parameters across rounds would compound two problems. Errors in early generated rationales would be reinforced by every subsequent round of training on data that descends from them, and the generating distribution would drift progressively away from its starting point. Restarting from M each time confines the role of the outer loop to improving the data: every iteration is a fresh fine-tune on the best dataset assembled so far, so gains come from data quality rather than from accumulated parameter updates. The cost is that each iteration repeats the full fine-tuning from the base checkpoint.

3 STaR as Approximate Policy Gradient

The loop can be read as an approximation to a reinforcement-learning objective, which clarifies why the filtering rule is the correct thing to do. Treat M as a latent-variable model in which the rationale is an unobserved variable sampled before the answer:

p_M(y \mid x) = \sum_{r} p(r \mid x)\, p(y \mid x, r).

The model first samples a latent rationale r from p(r \mid x), then produces an answer conditioned on the rationale. The decomposition matters because it identifies the rationale as the object being optimized: improving p_M(y \mid x) means shifting probability toward rationales that yield correct answers.

With the indicator reward \mathbf{1}(\hat{y} = y) — one for a correct answer, zero otherwise — the total expected reward over the dataset and its gradient are

J(M, X, Y) = \sum_i \mathbb{E}_{\hat{r}_i, \hat{y}_i \sim p_M(\cdot \mid x_i)} \mathbf{1}(\hat{y}_i = y_i),

\nabla J(M, X, Y) = \sum_i \mathbb{E}_{\hat{r}_i, \hat{y}_i \sim p_M(\cdot \mid x_i)} \left[ \mathbf{1}(\hat{y}_i = y_i) \cdot \nabla \log p_M(\hat{y}_i, \hat{r}_i \mid x_i) \right].

The gradient follows from the standard log-derivative identity for policy gradients, \nabla \mathbb{E}_{z \sim p_\theta}[f(z)] = \mathbb{E}_{z \sim p_\theta}[f(z)\,\nabla \log p_\theta(z)], which moves the gradient operator inside the expectation by differentiating the sampling distribution. The indicator multiplies the score-function term, so every sampled (\hat{r}_i, \hat{y}_i) whose answer is wrong contributes a zero gradient and drops out. The surviving terms are exactly the rationales that reach the correct answer, each pushed up by a log-likelihood gradient step. That is the filtering-and-fine-tuning rule, recovered from the objective: fine-tuning on the answer-correct rationales is one step of this policy gradient.

STaR departs from an exact estimate of \nabla J in two ways, each a deliberate simplification. First, instead of drawing many samples per problem to estimate the expectation, it greedily decodes a single sample. This reduces the variance of the estimate but biases the exploration of rationale space toward the model’s highest-probability continuation, so rationales the model considers unlikely are rarely seen. Second, after collecting a batch it takes several gradient steps on that same batch, as in policy-gradient methods such as PPO that reuse a batch of trajectories for multiple updates (Schulman et al. 2017). These approximations let STaR run on standard language-model fine-tuning machinery with no specialized RL infrastructure. The paper presents the connection as motivation rather than a proof of equivalence, and notes the link to the RL objective deserves closer study.

4 Rationalization: Learning From Failed Problems

The plain loop has a structural ceiling. The model trains only on problems it answers correctly, so a problem it cannot solve produces no surviving rationale and therefore no gradient. Once the model stops solving new problems in the training set, the data stops growing and improvement halts. The hardest problems — the ones most worth learning from — are precisely the ones that never enter the training set.

Rationalization removes this ceiling by changing what the model is asked to do on failed problems. The correct answer is added to the prompt as a hint, and the model is asked to produce a rationale in the same style, now reasoning backward from a known conclusion to a justification for it. When the resulting rationale reaches the correct answer, it is added to the training data — but with the hint removed from the prompt, so the example appears as though the model had produced the rationale unaided.

The off-policy reading of this is precise. Ordinary rationale generation samples from p(r \mid x), the model’s prior distribution over rationales given only the problem. Rationalization samples from p(r \mid x, y), the distribution conditioned on the answer. Conditioning on the answer narrows the search to rationales consistent with the known conclusion, which is a more productive region to sample from when the unconditioned model cannot find a correct rationale on its own. In the policy-gradient framing, rationalization is an off-policy estimate of the same objective, using the hint-augmented model as a proposal distribution. Its main benefit is exposing the model during fine-tuning to difficult problems that the plain loop would never include; a secondary benefit is a larger dataset. The paper is explicit that constructing the hint is straightforward for the tasks studied — the answer is simply inserted into the prompt — but may not be straightforward in general.

5 The Full Algorithm

One outer-loop iteration n runs four steps. The current model M_{n-1} attempts every problem by rationale generation, producing (\hat{r}_i, \hat{y}_i). It also attempts every problem by rationalization, producing (\hat{r}^{\,\text{rat}}_i, \hat{y}^{\,\text{rat}}_i) from the hint-augmented prompt. The generation dataset keeps problems answered correctly without a hint, \{(x_i, \hat{r}_i, y_i) : \hat{y}_i = y_i\}; the rationalization dataset keeps problems that were failed without a hint but solved correctly with one, \{(x_i, \hat{r}^{\,\text{rat}}_i, y_i) : \hat{y}_i \neq y_i \land \hat{y}^{\,\text{rat}}_i = y_i\}. The original model M is then fine-tuned on the union of the two sets to produce M_n. Dropping the rationalization steps recovers the plain loop. The fine-tune that produces M_n from a fixed dataset is the inner loop; the repeated generate–filter–retrain cycle is the outer loop.

6 Experiments

All experiments use GPT-J, a 6B-parameter model with a public checkpoint and fine-tuning code (Zelikman et al. 2022), on three tasks that differ in how strongly a correct answer constrains the reasoning behind it. On multi-digit addition the filter is tight — a wrong digit almost always yields a wrong sum — so whatever the loop produces is genuine: few-shot accuracy is under 1\% on 2-digit addition, yet after 16 iterations overall accuracy reaches 89.5\%, above the 76.3\% of a baseline trained directly on answer-only examples. Here rationalization mainly changes which problems enter the training set. Without it, progress is stage-wise, because a digit length joins the data only once the model can already solve it unaided; supplying the answer lets the model produce correct scratchpads for lengths it cannot yet solve, so 2-digit accuracy jumps from under 1\% to 32\% after one iteration, and continued training on new lengths later generalizes to unseen 9- and 10-digit problems.

On CommonsenseQA the filter is loose — five-way multiple choice scores about 20\% by chance — so some surviving rationales are correct by luck and the accuracies should be read against that floor. STaR reaches 72.5\%, against 73.0\% for a GPT-3 model roughly 30 times larger fine-tuned on the full dataset, while gaining +35.9 points over few-shot chain-of-thought and +12.5 over direct fine-tuning on the same GPT-J; rationale generation supplies correct rationales for 78.2\% of the training set and rationalization adds the 8.5\% difficult tail the plain loop never reaches. On GSM8K, grade-school word problems of two to eight steps (Cobbe et al. 2021), STaR roughly doubles the direct-fine-tuned accuracy from 5.8\% to about 10\% on a quarter of the data, but rationalization barely helps. The paper reports this without a cause; a reading consistent with the answer-constraint axis — offered as interpretation, not a claim from the paper — is that a multiple-choice letter strongly pins down a one-step justification, whereas a single number leaves an eight-step derivation underdetermined, so conditioning on it gives little guidance.

7 Rationale Quality

Answer accuracy does not directly measure rationale quality, which for natural-language tasks can only be assessed by inspection. In a preliminary study, 50 rationales each from few-shot chain-of-thought, from STaR, and human-written rationales were drawn from problems all sources answered correctly, and 20 crowdworkers ranked them by how well they justified the answer. Participants were 30% more likely to rank STaR rationales above the few-shot rationales (p = 0.039) and 74% more likely to prefer STaR rationales over the human-written ones (p < 0.001). The paper reads the second result not as evidence of human-level rationale generation but as evidence that eliciting high-quality rationales from people is itself difficult.

The paper also catalogs failure modes in the generated rationales whose final answers are nonetheless correct: restating the question’s property without explaining why the chosen answer satisfies it, presupposing the answer within the reasoning, declining to justify the answer at all, and asserting facts about a named individual rather than the general class the individual belongs to.

8 Why Not Just Sample at Higher Temperature

A natural alternative for enlarging the dataset is to draw more samples at a higher temperature rather than to rationalize. The paper finds this counterproductive. Higher temperature raises the rate of correct answers reached through incorrect reasoning, and fine-tuning on bad reasoning harms generalization; in arithmetic the high-temperature scratchpads degrade into meaningless sequences and the model stagnates. Temperatures of 0.5 and 0.7 consistently produced worse models than low-temperature reasoning alone. Higher-temperature sampling is also more expensive, since text is generated token by token and drawing ten samples is about ten times slower than drawing one. The paper suggests that majority vote over multiple high-temperature samples, in the manner of self-consistency, could instead serve as a substitute label, which would in principle allow STaR to run on questions with no answer labels.

9 Limitations

STaR’s first iteration depends on the base model already reasoning above chance few-shot, since otherwise the filter has nothing correct to keep — the paper reports that GPT-2 could not bootstrap even on arithmetic, so the base model must be large enough to have some reasoning ability. Tasks with high chance accuracy, such as binary decisions, produce many rationales that are correct by luck and poor in reasoning, and filtering on the answer alone cannot remove them; how to filter bad reasoning in that regime is left open. The hint construction that drives rationalization is simple for these tasks but may not generalize.

10 Conclusion

STaR turns a small set of rationale examples and a large answer-labeled dataset into a self-improving loop: the model generates rationales, the answer label filters them, fine-tuning on the survivors yields a stronger model, and the cycle repeats. Rationalization extends the signal to problems the model cannot yet solve by letting it reason backward from the given answer. The objective behind the loop is an approximate policy gradient in which the answer indicator is the reward and filtering is exactly the gradient’s selection of correct samples. On arithmetic, CommonsenseQA, and GSM8K the method improves substantially over both few-shot prompting and direct answer fine-tuning, and on CommonsenseQA it approaches a model 30 times larger while training on a fraction of the data.
