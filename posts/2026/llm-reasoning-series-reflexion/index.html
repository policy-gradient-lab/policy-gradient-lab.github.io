Reflexion is a framework that lets an agent improve across repeated attempts at a task without updating any weights (Shinn et al. 2023). After a failed trial, the agent converts the environment’s feedback into a natural-language summary of what went wrong and what to do differently, stores that summary in a memory buffer, and includes it in the prompt for the next attempt. The model is held fixed; what changes between trials is the text in its context. The paper reports gains over strong baselines on three task types: an absolute 22% on AlfWorld decision-making, 20% on HotPotQA reasoning, and 11% on HumanEval code generation. It also reports a 91% pass@1 accuracy on HumanEval, above the 80% reported for GPT-4 at the time.

1 The Policy Is the Memory, Not the Weights

The reframing that organizes the whole method is in how Reflexion defines the policy being optimized. In policy-based reinforcement learning an agent samples an action a_t from a policy \pi_\theta(a_t \mid s_t) parameterized by weights \theta, and learning means changing \theta. Reflexion keeps the policy-gradient vocabulary but redefines the parameters:

\theta = \{M_a,\ mem\}.

Here M_a is the fixed language model that generates actions and mem is the agent’s memory of past self-reflections. Optimization no longer touches the weights of M_a; it edits the contents of mem. The policy is the pair (frozen model, accumulated text), and the only mutable part is the text.

This definition is doing more than relabeling. By placing the optimization in mem, the method makes a deliberate trade. Gradient updates to \theta would propagate a scalar reward over the model’s parameters through credit assignment that the optimizer performs implicitly and opaquely. Updates to mem are explicit, human-readable strings appended to a buffer. The cost is that improvement is bounded by what the language model can extract from its own context and act on, with no formal guarantee of convergence or success. The benefit is that no fine-tuning is required, the feedback can be far more specific than a scalar, and the agent’s accumulated “experience” is directly inspectable.

2 Three Models: Actor, Evaluator, Self-Reflection

The framework is built from three components, each instantiated as a language model or a fixed function.

The Actor M_a generates text and actions conditioned on the current state and on memory. It is the policy in the sense above. The paper instantiates it with existing prompting strategies, namely Chain-of-Thought for single-step reasoning and ReAct for multi-step interaction (Yao et al. 2023), so Reflexion sits on top of an action generator rather than replacing it. The memory mem is supplied to the Actor as additional context, an approach the authors attribute to prior work using in-context learning for policy iteration.

The Evaluator M_e takes a completed trajectory and produces a reward score measuring how well it performed. The paper uses different Evaluators for different tasks because there is no single reward function that applies across semantic spaces: exact-match grading for reasoning answers, hand-written heuristics for decision-making, and in some cases a separate instance of a language model prompted to judge success.

The Self-Reflection model M_{sr} is the component specific to Reflexion. Given the trajectory, the reward signal, and the current memory, it generates a verbal reflection, a few sentences naming the likely cause of failure and a corrective plan, which is then appended to memory. This is where a sparse signal such as a single success/fail bit is turned into the specific, actionable text the Actor will read on the next trial.

A representative reflection, from an AlfWorld trial in which the agent was told to examine a mug with a desk lamp and instead searched for the mug first: “my plan was to find a mug then find and use a desklamp. However, the task says to examine the mug with the desklamp. I should have looked for the desklamp first… In the next trial, I will go to desk 1, find the lamp, then look for the mug and examine it with the desklamp.” On the following trial the agent goes directly to the lamp and succeeds.

3 From Scalar Reward to Verbal Feedback

The mechanism that makes the memory useful is the conversion of the Evaluator’s score into language. The Evaluator produces a scalar for trial t,

r_t = M_e(\tau_t),

where \tau_t is the trajectory. On its own r_t carries almost no information for an LLM agent: a binary success/fail bit, or a number, says that the attempt was wrong but not where or why. The Self-Reflection model takes the pair \{\tau_t, r_t\} and produces a textual summary

sr_t = M_{sr}(\tau_t,\ r_t),

which is stored in memory. The paper describes the resulting text as acting as a “‘semantic’ gradient signal,” its own term and in quotation marks there, because it gives the agent a concrete direction to move in rather than only a magnitude of error.

Why convert the scalar to language at all, rather than feeding the reward directly to the next trial? The answer is credit assignment. In a multi-step trajectory the reward is received only at the end, and a scalar does not indicate which action was responsible for the outcome. A language reflection can: it can state that a specific early action a_i led to subsequent incorrect actions and that a different action a_i' should have been taken, localizing the error in a way a single number cannot. This is the same credit-assignment problem that value-based RL addresses with a learned value function; Reflexion addresses it by having a language model write down, in natural language, an attribution of blame and a correction. The feedback is more nuanced than a scalar or vector reward precisely because the space of possible reflections is the space of natural language.

4 The Reflexion Loop

The three models run in a loop. The Actor produces an initial trajectory \tau_0; the Evaluator scores it as r_0; the Self-Reflection model produces sr_0 and sets memory to [sr_0]. Then, while the Evaluator has not signaled success and the trial count is below a maximum, the Actor generates a new trajectory using the current memory, the Evaluator scores it, the Self-Reflection model produces a new reflection sr_t, and that reflection is appended to memory. The loop terminates when the Evaluator deems a trajectory correct or the trial budget is exhausted.

Memory is split into two parts with different roles. Short-term memory is the trajectory history within the current trial, the fine-grained record of recent actions and observations. Long-term memory is the set of accumulated reflections sr_t across trials. The Actor conditions on both: the short-term trajectory gives it the immediate context of the current attempt, and the long-term reflections give it the distilled lessons of previous failures.

Long-term memory is bounded. The buffer is limited to a maximum number of stored reflections, which the paper denotes \Omega and describes as “usually set to 1-3,” with older reflections evicted as new ones arrive once the bound is reached. The bound exists for a concrete reason rather than as a design preference. Each stored reflection is text prepended to every subsequent prompt, and a language model has a fixed maximum context length. An unbounded memory would eventually overflow that window. Keeping \Omega small (the programming experiments use a single stored experience, the reasoning and decision-making experiments use three) keeps the accumulated reflections inside the context budget while retaining the most recent and presumably most relevant lessons. The paper notes this sliding-window scheme as a limitation and points to external storage, such as vector databases, as a way to lift the bound in future work.

5 Where the Evaluation Signal Comes From

Reflexion’s claim to be lightweight depends on being able to produce a reward signal without weight updates and, ideally, without ground-truth supervision at test time. The paper uses three sources of signal, and the difference between them matters for how trustworthy the resulting reflections are.

The first is direct binary feedback from the environment, a success/fail bit that the environment itself emits. The second is pre-defined heuristics targeting common failure modes. In AlfWorld the heuristic is explicit: if the agent repeats the same action and receives the same response more than three times, or takes more than 30 actions in an environment, the trajectory is judged to have failed through hallucination or inefficient planning, and a reflection is triggered. The third is self-evaluation, in which a separate instance of a language model classifies the trajectory as successful or not.

For programming the evaluation signal is self-generated unit tests, which is the most grounded of the variants because it runs real code against real assertions. The agent uses Chain-of-Thought prompting to produce candidate tests with natural-language descriptions, filters them by attempting to build a valid abstract syntax tree for each so that syntactically invalid tests are discarded, and samples a test suite T = \{t_0, t_1, \dots, t_n\} with n capped at six. Because correctness is judged by executing self-written tests rather than by consulting hidden reference tests, the programming setup remains eligible for pass@1 reporting, since the agent never sees test cases it would not have access to at deployment.

6 Decision-Making

AlfWorld is a suite of text-based household environments requiring multi-step tasks such as finding a hidden object, moving an object, or manipulating one object with another. The paper runs the agent in 134 environments using ReAct as the action generator, with the failure heuristic above triggering self-reflection. In the baseline, when a trajectory is judged failed the environment is reset and a fresh trial begins with no reflection; in the Reflexion condition the agent first writes a reflection, then resets.

ReAct with Reflexion completes 130 of 134 tasks and continues to solve additional tasks over twelve consecutive trials, whereas the ReAct-only baseline stops improving between trials six and seven and converges at a hallucination rate of 22%. The improvement comes from two failure modes that long-term memory addresses: an early mistake in a long trajectory that the agent can identify and correct on the next attempt, and an environment with many locations to search, where the agent can use memory across trials to search systematically rather than repeating itself. The baseline’s characteristic failure is an agent that believes it holds an item it never picked up and then cannot backtrack to find the error; the reflection distills the long failed trajectory into a short reusable hint.

7 Reasoning

HotPotQA is a question-answering dataset whose questions require reasoning over several supporting Wikipedia documents. The paper tests two configurations: Chain-of-Thought given the ground-truth supporting context, which isolates reasoning ability, and ReAct with Wikipedia retrieval, which tests reasoning and action choice together. Between trials, exact-match grading against the reference answer supplies the binary signal that the self-reflection step amplifies, with a memory of three experiences. The baselines (ReAct-only, CoT-only, and CoT-with-ground-truth-only) fail to improve on any previously failed task across trials: with no mechanism to carry information between attempts, re-running the same question at temperature 0.7 does not solve it.

The most informative result is an ablation that separates two things conflated in the full method: having any record of the previous attempt, versus having a reflection on it. The authors start from CoT with ground-truth context, add an episodic memory consisting of the most recent trajectory, and then, for the full Reflexion agent, add the self-reflection step on top. Episodic memory alone, meaning the raw previous trajectory in context, produces some gain, and adding the self-reflection step yields a further 8% absolute improvement over the episodic-memory condition. Supplying the previous attempt is not equivalent to reflecting on it; the verbal analysis of why the attempt failed contributes measurably beyond the presence of the trajectory itself. The same configuration shows that even with ground-truth context the CoT agent fails on 39% of questions, and Reflexion recovers 14% of accuracy on those without access to the answer.

8 Programming

On code generation Reflexion sets new state-of-the-art pass@1 results on most benchmark and language pairs: HumanEval Python rises to 91.0 from a prior best of 80.1 (GPT-4), HumanEval Rust to 68.0 from 60.0, MBPP Rust to 75.4 from 70.9, and Leetcode Hard Python to 15.0 from 7.5. The exception is MBPP Python, where Reflexion reaches 77.1 against the 80.1 GPT-4 baseline.

The MBPP Python result is worth dwelling on because it exposes the method’s dependence on the quality of its self-generated tests. The agent’s evaluation signal is its own unit tests, so two error types are possible. A false positive occurs when a flawed implementation passes all self-written tests; a false negative occurs when a correct implementation fails a badly written test. Reflexion tolerates false negatives reasonably well, since the agent can use reflection to suspect a bad test and keep its original code, but a false positive is unrecoverable, because the agent concludes it has succeeded and stops. The paper measures the false-positive rate of internal test execution and finds it is 1.4% on HumanEval Python but 16.3% on MBPP Python, while the baseline pass@1 accuracies of the two are similar (82% and 80%). The high false-positive rate on MBPP is what drags Reflexion below the baseline there: the agent frequently certifies wrong solutions as correct and never revises them.

A second ablation, on the 50 hardest HumanEval Rust problems with GPT-4, separates the two cooperating components, test generation and self-reflection. The base model scores 0.60. Removing test generation but keeping reflection drops accuracy to 0.52, below the base model, because without unit tests the agent cannot tell whether its current implementation is correct, so it edits code through every iteration with no way to stop early and makes it worse. Removing reflection but keeping test generation returns 0.60, no gain over the base model: the tests catch errors but the agent, asked to identify and fix faults in one step without writing out a reflection, does not translate the test failures into correct edits. Only the full method, with both components, reaches 0.68. The reading the authors draw is that blind trial-and-error debugging without an explicit reflection step is ineffective on harder programming tasks.

9 Limitations

Reflexion is, in the authors’ framing, policy optimization conducted in natural language, and it inherits a standard weakness of policy optimization: it can settle into non-optimal local minima. The paper reports this concretely on WebShop, an e-commerce navigation benchmark, where a ReAct-with-Reflexion agent shows no improvement over four trials and the runs are terminated early. The diagnosis is that WebShop requires diverse, exploratory search behavior, and the agent does not generate useful reflections when the path to success requires substantial exploration rather than correcting an identifiable mistake; tasks where the action space is visible in observations, as in AlfWorld, are more tractable for it.

Two further limits are structural. Long-term memory is the bounded sliding window described above, which discards older experience. And for code generation the reliance on self-generated tests inherits the limits of test-driven development: it cannot specify accurate input-output behavior for non-deterministic functions, impure functions that call external APIs, hardware-dependent functions, or concurrent code, so the self-evaluation signal is unreliable exactly where program behavior is hard to predict.

10 Putting It Together

Reflexion treats the prompt context as the object of optimization. The model’s weights stay fixed; what is updated between attempts is a small buffer of natural-language reflections, generated by converting a sparse reward into a localized, written account of what failed and what to change. This buys explicit, inspectable credit assignment and removes the cost of fine-tuning, at the price of depending on the language model’s ability to evaluate itself and to act on its own written advice. The empirical pattern across the three task types is consistent on this point: the gains come not merely from retrying or from carrying the previous trajectory forward, but from the verbal reflection step specifically. The reasoning ablation isolates an 8% contribution from it, and the programming ablation shows that test feedback without reflection produces no improvement over the base model.
